1D.1 Radius of gyration

In this exercise, we compute the radius of gyration of a protein structure.

The radius of gyration \(R_g\) is defined as

\[R_g=\sqrt{\frac{\sum_{j=1}^{N}m_j \Delta \mathbf{r_j} \cdot \Delta \mathbf{r_j}}{\sum_{j=1}^{N}m_j}} ,\]

where \(\mathbf{r_j}\) is the coordinate vector of atom \(j\) (its x, y, and z values), \(m_j\) is the atomic mass of atom \(j\), and \(N\) is the total number of atoms. The center of mass \(\mathbf{\overline{r}}\) is

\[\mathbf{\overline{r}}=\frac{\sum_{j=1}^{N}m_j\mathbf{r_j}}{\sum_{j=1}^{N}m_j} ,\]

and the displacement vector \(\Delta \mathbf{r_j}\) is \(\mathbf{r_j} - \mathbf{\overline{r}}\).

Python implementation

Bio.PDB (from biopython) plays the same role. This helper downloads a structure and collects its atomic coordinates into a pandas DataFrame:

import tempfile
from Bio import PDB
import pandas as pd

def pdb_to_dataframe(pdb_id):
    pdbl = PDB.PDBList()
    pdb_file_path = pdbl.retrieve_pdb_file(pdb_id, pdir=tempfile.gettempdir(), file_format="pdb")
    pdb_parser = PDB.PDBParser(QUIET=True)
    structure = pdb_parser.get_structure(pdb_id, pdb_file_path)
    atom_data = []
    for model in structure:
        for chain in model:
            for residue in chain:
                for atom in residue:
                    atom_data.append({
                        "atom_name": atom.get_name(),
                        "residue_name": residue.resname,
                        "chain_id": chain.id,
                        "residue_number": residue.id[1],
                        "x": atom.coord[0],
                        "y": atom.coord[1],
                        "z": atom.coord[2],
                        "b": atom.bfactor,
                    })
    return pd.DataFrame(atom_data)

coord = pdb_to_dataframe("7l3u")

1D.3 Stirling’s approximation

The naive way to compute \(\ln n!\) is to take the log of the factorial directly:

R implementation

ln_fact <- function(n) {
  return(log(factorial(n)))
}
ln_fact(10)
[1] 15.10441
ln_fact(170)
[1] 706.5731
ln_fact(171)
[1] Inf

Python implementation

import math

def ln_fact(n):
    return math.log(math.factorial(n))

ln_fact(10)
15.104412573075516
ln_fact(170)
706.5730622457874
ln_fact(1000)
5912.128178488163

R’s factorial(171) returns Inf, so ln_fact breaks there: R represents factorial(n) as a double, and doubles overflow past about \(1.8 \times 10^{308}\), which \(171!\) already exceeds. Python’s math.factorial instead returns an arbitrary-precision integer, so ln_fact(1000) still gives a finite answer, but try ln_fact(100000) and time it: multiplying out a thousands-of-digits integer, one factor at a time, gets slow well before it overflows anything.

Both languages hit a wall for large \(n\), just for different reasons and at different points (think about why, for each). A more scalable approach avoids forming \(n!\) at all and instead sums logs directly:

\[f(n) = \ln n!=\sum_{j=1}^{n}\ln j .\]

(a) Benchmarking. Implement \(f(n)\) for large \(n\) using each of the following, in both R and Python:

  1. a loop that accumulates the sum term by term;
  2. a vectorized sum (R: sum(log(1:n)); Python: numpy);
  3. an apply-family construct (R: sapply/vapply; Python: map, or a list comprehension);
  4. a compiled C or Fortran routine, called the way Part 1B calls compiled code.

Benchmark each method’s runtime (R: microbenchmark; Python: timeit) for a moderately large \(n\) (say \(10^5\) or \(10^6\)), consistent with the previous chapter.

(b) Deviation of Stirling’s approximation. Stirling’s approximation (Stirling 1730) states

\[\ln n! \approx n\ln n - n .\]

Using any method from (a) to compute the left-hand side, plot the relative deviation

\[1-\frac{n\ln n - n}{\ln n!}\]

as a function of \(n\), and describe how it behaves as \(n\) grows.

Stirling, James. 1730. Methodus Differentialis: Sive Tractatus de Summatione Et Interpolatione Serierum Infinitarum. G. Bowyer. https://archive.org/details/methodusdifferen00stir.
